# インフラ構成図

どこで何が動き、どの経路で通信するかを描く。AWS 構成図、ネットワーク構成図がこれに当たる。

## 記法

- AWS のサービスは draw.io の AWS アイコン（`mxgraph.aws4.*`）で描き、AWS Cloud・リージョン・VPC・サブネットの枠で包む
- AWS の外のサービス（GitHub などの SaaS）は AWS Cloud 枠の外に「外部サービス」の枠を作って置き、全ページで置き方を揃える。ロゴは draw.io の `mxgraph.weblogos.*`（例: `shape=mxgraph.weblogos.github`）を使う
- オンプレミスや拠点は AWS Cloud 枠の外に置き、VPN / Direct Connect の経路を線で描く
- 矢印は通信の向きで描き、必要ならポート・プロトコルをラベルに書く

## AWS 構成を検証する

AWS のサービスを含む図では、書き出す前に、図が描いている内容が AWS の公式ドキュメントと合っているかを AWS Knowledge MCP で確かめる。
記憶にある仕様は古くなっていることがあり、存在しない連携や、そのリージョンで使えないサービスを描いたまま資料に載ると、お客様の前で訂正することになるためである。

検証の対象は、図から読み取れる主張のすべて。

- 矢印で描いた連携（例: ALB → VPC Lattice のターゲット、CodePipeline → 自前の Git サーバー）が、その方向・その方式で実現できるか
- ラベルに書いた機能や設定（例: 「CodeDeploy 不要」「VPC オリジン」「jp. 推論プロファイル」）が実在し、書いたとおりに動くか
- リージョングループに置いたサービスが、そのリージョンで提供されているか
- VPC の中に置いたサービスが、VPC エンドポイントなど閉域の経路で届くか

| 確かめること | ツール |
| --- | --- |
| 連携・機能・設定の可否 | `mcp__aws-knowledge__aws___search_documentation` で探し、返ってきた本文の抜粋で判断する。抜粋で足りないときだけ `aws___read_documentation` で全文を読む |
| リージョンでの提供状況 | `mcp__aws-knowledge__aws___get_regional_availability` |

主張ごとに「可 / 条件付き / 不可 / 未確認」と出典 URL を控え、全件に判定が付いたら完了。
「不可」は `.drawio` を直す。
「条件付き」と「未確認」は図のままにして、報告で条件や確認方法を添える。
図と同じディレクトリに構成の補足資料（`*-notes.md` など）があれば、判定と出典をそちらの実現可能性の一覧にも反映する。

## 確認

- AWS 構成の検証で、全ての主張に判定が付いている
- 全ページで、外部サービスの枠の置き方が揃っている
